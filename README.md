# Оцінка ефективності алгоритмів розрахунку решти

## Опис задачі

Метою є розробка двох алгоритмів для видачі решти покупцеві за допомогою заданого набору монет [50, 25, 10, 5, 2, 1]:
1. **Жадібний алгоритм** (greedy) — вибирає найбільший доступний номінал монети на кожному кроці.
2. **Динамічне програмування** (DP) — знаходить мінімальну кількість монет для формування заданої суми.

## Опис реалізації

### Жадібний алгоритм (`find_coins_greedy.py`)
Жадібний підхід працює шляхом вибору найбільшої можливої монети та повторення цього процесу, доки сума не буде покрита.
- **Переваги**: швидка реалізація, ефективний для наборів монет, які підтримують оптимальність жадібного підходу.
- **Недоліки**: не завжди дає мінімальну кількість монет. Наприклад, якщо у нас є монети [9, 6, 1] і потрібно видати решту 12, жадібний алгоритм видасть {9: 1, 1: 3}, а оптимальне рішення – {6: 2}.

### Динамічне програмування (`find_min_coins.py`)
Алгоритм заснований на підході «знизу вгору», де будується масив оптимальних рішень для всіх значень від 0 до заданої суми.
- **Переваги**: знаходить дійсно мінімальну кількість монет.
- **Недоліки**: вимагає більше пам’яті та часу, ніж жадібний алгоритм, особливо для великих значень.

## Порівняння ефективності

| Алгоритм | Часова складність | Пам'ять | Оптимальність рішення |
|----------|------------------|---------|----------------------|
| Жадібний | O(n) | O(1) | Не завжди оптимальний |
| Динамічне програмування | O(n * m) | O(n) | Завжди оптимальний |

де `n` — сума, `m` — кількість номіналів монет.

## Висновки

- Жадібний алгоритм є швидким і добре працює для стандартних валютних систем.
- Динамічне програмування гарантує мінімальну кількість монет, але може бути менш ефективним у плані пам’яті та швидкості.
- Для великих сум жадібний алгоритм працює швидше, але якщо важлива мінімізація кількості монет, динамічне програмування є кращим вибором.
